Создайте `01_txt/events.txt` в кодировке UTF-8:


**Проверка:** всего **8** событий; `INFO` — **3**, `WARNING` — **2**, `ERROR` — **3**.

### Задача 1.2. Сформировать текстовый отчёт

- Создайте `errors.txt` только с ошибками уровня `ERROR` в виде `дата — сообщение`.
- Создайте `summary.txt` с количеством записей каждого уровня и общим числом событий.
- Для записи используйте `open(..., "w", encoding="utf-8")`. Повторный запуск должен заменять предыдущие отчёты, а не дописывать копии строк.

**Проверка:** в `errors.txt` должно быть **3** строки.

### ★ Задача 1.3. Поиск по дате — необязательно

## 2. Словари Python — статистика заказов

Создайте `02_dict/main.py` и поместите в него данные. Здесь **не нужно читать файл** — отрабатываем словари и списки словарей:

```python
orders = [
    {"id": 101, "category": "Книги", "price": 500, "qty": 2, "status": "paid"},
```

### Задача 2.1. Подсчёт оплаченных заказов

- Переберите список циклом `for`; учитывайте только записи со статусом `paid`.
- Для каждого оплаченного заказа вычислите стоимость `price * qty`.
- Выведите количество оплаченных заказов и общую выручку. В коде используйте обращение к словарю по ключу и хотя бы один вызов `get()`.

**Проверка:** **5** оплаченных заказов, общая выручка **5850 руб.**

### Задача 2.2. Группировка по категориям

- Создайте словарь, где ключ — категория, а значение — общая выручка этой категории.
- Накопление сумм реализуйте через `get()` или `setdefault()`; используйте `items()` для вывода результата.

**Проверка:** `Книги` — **1800**, `Электроника` — **3200**, `Канцелярия` — **850**.

### ★ Задача 2.3. Вложенная статистика

Для каждой категории храните **и сумму, и количество оплаченных заказов**: `{"Книги": {"amount": 1800, "count": 2}, ...}`. Выведите категорию с наибольшей выручкой. Используйте обычные циклы, без сторонних библиотек.

## 7. Преобразование и проверка данных — очистка регистраций

```csv

3;Ирина;29;irina.example.org;confirmed
```

### Задача 7.1. Проверить поля и отсеять ошибки

### Задача 7.2. Сохранить корректные записи и ошибки

- Создайте `summary.json` с полями `total`, `valid`, `invalid`, `confirmed`, `cancelled`. Последние два показателя вычисляйте **только по корректным записям**.
- Не заменяйте исходный файл. При повторном запуске все три отчёта должны обновляться без дублирования записей.

**Проверка:** `total` — **9**, `valid` — **4**, `invalid` — **5**, `confirmed` — **3**, `cancelled` — **1**; в `errors.csv` — **5** строк данных плюс заголовок.
